# 작업공간 프로토콜

## 기본 구조

대상 프로젝트에는 `.agent-company/`가 생성된다. 역할별 git worktree는 대상 repo 옆의 `.<repo-name>-agent-company-worktrees/` 아래에 생성된다.

## 쓰기 권한 원칙

모든 직원은 완료 파일을 작성해야 하므로 기술적으로는 `workspace-write`로 실행된다. 기획자, 리서처, UI/UX 디자이너, 아키텍트, 릴리즈 담당자는 행동 규칙상 소스 수정이 금지된다. 개발자는 구현 worktree에서 수정한다. QA는 검증을 우선하고 수정은 대표가 명시적으로 요청한 경우에 한정한다.

## 충돌 방지

여러 직원이 같은 파일을 동시에 수정하지 않도록 대표가 칸반 작업 단위를 작게 쪼개고 담당자를 명확히 지정한다.

## 동료 메시지

직원 간 직접 메시지는 `.agent-company/messages/`와 대상 직원 inbox에만 기록한다. 메시지는 소스 수정 권한을 부여하지 않으며, 다른 직원의 작업 파일이나 완료 파일을 대신 작성하지 않는다.
