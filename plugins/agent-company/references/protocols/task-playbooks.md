# 작업 플레이북

## planning

- 문제 정의, 권장 범위, 성공 기준, 확인 질문을 정리한다.
- 합의 입장은 범위와 성공 기준이 충분한지 기준으로 남긴다.

## research

- 확인된 사실과 출처, 추정, 후보 평가, 리스크를 분리한다.
- 최신 정보가 필요하면 확인 범위와 날짜를 명시한다.

## design

- 사용자 흐름, 화면 구조, 상호작용, 접근성 기준을 제안한다.
- 구현자가 바로 판단할 수 있는 화면 요구사항을 남긴다.

## architecture

- 권장 구조, 데이터 흐름, 리스크, 구현 순서를 정리한다.
- 모듈 경계와 공개 인터페이스 변경 여부를 명확히 한다.

## implementation

- 승인된 범위 안에서 패치 제안을 만든다.
- 변경 파일, 검증 방법, 남은 리스크를 함께 보고한다.
- 새 제품 판단이 필요하면 구현하지 말고 `needs-user` 입장을 남긴다.

## qa

- 테스트 관점, 수동 확인, 자동 검증, 차단 이슈를 정리한다.
- 실제 실행한 검증과 제안 검증을 구분한다.

## release

- 릴리즈 노트, 배포 체크리스트, 롤백, 승인 필요 항목을 정리한다.
- 실제 배포나 push는 하지 않는다.

## knowledge

- 결정사항, 근거, 열린 질문, 다음 액션을 재개 가능한 형태로 정리한다.

## general

- CEO 계획, 회의 운영, 합의 판단, 최종 보고처럼 여러 역할을 조율하는 작업에 사용한다.
